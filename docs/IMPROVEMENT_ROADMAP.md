# 改进路线图

本路线图基于 2026-07-29 对当前仓库的代码、依赖、运行入口和 Git 状态进行的静态审查。目标是把一次性演示项目逐步改造成可验证、可移植、可维护的系统，而不是一次性升级所有依赖。

## 本次改进

- 修复异步函数经过 `with_circuit_breaker` 装饰后没有被真正等待的问题。
- 让异步调用的成功、异常、重试和退避都由熔断器观察。
- 增加第一组标准库单元测试，不安装模型或深度学习依赖也能验证核心可靠性逻辑。
- 将已弃用的 `asyncio.iscoroutinefunction` 改为 `inspect.iscoroutinefunction`，兼容较新的 Python。

## P1：运行时可移植性

当前代码与单机 RTX 4070/CUDA/Qwen2-7B 环境耦合较深：

- 多个模块直接判断或调用 CUDA。
- 模型路径写死为相对目录 `./models/Qwen2-7B`。
- CPU、Apple MPS、CUDA 和远程 API 没有统一的模型接口。
- 基础 Web/API 功能与本地大模型依赖没有拆分安装。

建议：

1. 定义统一的模型提供者接口，将本地 Hugging Face、远程 API 和规则降级实现分离。
2. 将设备选择集中到一个模块，明确支持 CUDA、MPS 和 CPU。
3. 使用配置或环境变量指定模型路径，不依赖启动时的当前工作目录。
4. 把依赖拆分成基础、模型和开发三组，让 API、解析器和单元测试可以轻量安装。

## P1：安全默认值

- API 当前允许任意 CORS 来源并启用凭据，应改为由环境变量提供明确白名单。
- `web_demo/run_demo.py` 使用 `shell=True` 启动固定命令；应改为参数列表并设置明确工作目录。
- API 捕获大量宽泛异常，部分错误可能被转换成正常响应；应统一错误类型、状态码和日志字段。

## P1：测试与持续集成

当前仓库原先没有自动化测试或 CI。建议优先覆盖：

1. 路由智能体对 SQL 注入、XSS、CVE 和异常连接的选择结果。
2. 日志解析器的无效 JSON、非法 IP、缺失字段和编码输入。
3. 结果融合的空结果、冲突结果和低置信度边界。
4. 熔断器的 OPEN、HALF_OPEN、CLOSED 状态转换。
5. FastAPI 的健康检查、输入验证和 CORS 配置。

完成基础测试后，再增加 GitHub Actions，运行语法检查、标准库测试和轻量 API 测试；不要在普通 CI 中下载 7B 模型。

## P2：依赖维护

当前依赖被整体固定在同一时期的版本。不要一次性全部升级：

1. 先建立基础测试基线。
2. 分组升级 Web/API、数据处理、RAG 和模型依赖。
3. 每组升级后运行测试和最小启动验证。
4. 对仅在 CUDA 环境可用的依赖使用平台标记或独立安装文件。

## P2：演示与文档收敛

`web_demo` 中存在多份功能相近的 Streamlit 脚本。建议保留一个正式入口、一个静态演示和必要的数据转换工具，其余版本在确认不再使用后删除。

文档中的吞吐量、准确率和“验证成功”结论应关联可重复执行的测试或基准命令，避免把历史演示结果当作当前运行保证。
