## 1. 快速入门

### 1.1 系统简介
基于多智能体协同的网络安全威胁智能分析系统是一款革命性的安全分析工具，采用先进的大语言模型技术，能够智能识别和分析各类网络威胁。

### 1.2 核心功能
- **智能威胁识别**：自动识别SQL注入、XSS、命令注入等攻击
- **风险评估**：实时计算风险评分（0-10分）
- **处置建议**：提供专业的安全处置建议
- **批量处理**：支持批量分析大量告警
- **可视化报告**：生成详细的分析报告

### 1.3 最快使用方式

#### 方式一：独立分析工具（推荐新手）
```bash
# 1. 进入项目目录
cd network-threat-analysis

# 2. 运行分析工具
python standalone_test.py

# 3. 查看结果
# 分析结果会保存在当前目录的JSON和Excel文件中
```

#### 方式二：API服务
```bash
# 启动API服务
python -m uvicorn src.api.server:app --port 8000

# 访问API文档
# 浏览器打开：http://localhost:8000/docs
```

## 2. 安装部署

### 2.1 环境要求

#### 最低配置
- **操作系统**：Windows 10/11, Ubuntu 18.04+, CentOS 7+
- **Python版本**：3.9+
- **内存**：16GB
- **存储空间**：50GB
- **GPU**：NVIDIA GPU（可选，CPU模式下较慢）

#### 推荐配置
- **操作系统**：Windows 11, Ubuntu 20.04+
- **Python版本**：3.10
- **内存**：32GB
- **存储空间**：100GB SSD
- **GPU**：NVIDIA RTX 4070 SUPER 12GB或更高

### 2.2 安装步骤

#### 步骤1：下载项目
```bash
git clone https://github.com/your-org/network-threat-analysis.git
cd network-threat-analysis
```

#### 步骤2：创建Python虚拟环境
```bash
# Windows
python -m venv venv
venv\Scripts\activate

# Linux/Mac
python3 -m venv venv
source venv/bin/activate
```

#### 步骤3：安装依赖
```bash
pip install -r requirements.txt
```

#### 步骤4：下载模型（首次运行）
```bash
python scripts/download_models.py
```

### 2.3 配置说明

主要配置文件：`config/config.yaml`

```yaml
# 模型配置
model:
  name: "Qwen2-7B-Instruct"

  device: "cuda"  # 或 "cpu"

  vector_db_path: "./vector_db"
  top_k: 5

# 日志配置
logging:
  level: "INFO"
  file: "./logs/system.log"
```

## 3. 功能说明

### 3.1 支持的攻击类型

| 类别 | 攻击类型 | 说明 |
|------|---------|------|
| Web攻击 | SQL注入 | 通过SQL语句攻击数据库 |
| Web攻击 | XSS攻击 | 跨站脚本攻击 |
| Web攻击 | CSRF攻击 | 跨站请求伪造 |
| Web攻击 | 文件上传 | 恶意文件上传 |
| Web攻击 | 命令注入 | 系统命令注入 |
| 漏洞利用 | 缓冲区溢出 | 内存缓冲区溢出攻击 |
| 漏洞利用 | 提权攻击 | 权限提升攻击 |
| 漏洞利用 | 0day利用 | 未知漏洞利用 |
| 非法连接 | 恶意IP | 来自恶意IP的连接 |
| 非法连接 | C&C通信 | 命令控制通信 |
| 非法连接 | 数据泄露 | 敏感数据外传 |

### 3.2 风险等级说明

| 风险分值 | 等级 | 颜色 | 处理建议 |
|---------|------|------|---------|
| 0-2 | 低风险 | 绿色 | 记录，定期回顾 |
| 3-5 | 中风险 | 黄色 | 监控，准备处置 |
| 6-8 | 高风险 | 橙色 | 立即处置 |
| 9-10 | 严重 | 红色 | 紧急处置 |

### 3.3 数据格式支持

- **JSON**：结构化告警数据
- **CSV**：表格格式数据
- **LOG**：系统日志文件
- **Excel**：.xlsx格式文件

## 5. 常见问题

### 5.1 安装问题

**Q: 提示"CUDA out of memory"怎么办？**
A: 解决方案：
1. 减少batch_size配置
2. 使用CPU模式：设置config中的device为"cpu"
3. 关闭不必要的GPU程序

**Q: 模型下载失败怎么办？**
A:
1. 检查网络连接
2. 使用代理：`export HF_ENDPOINT=https://hf-mirror.com`
3. 手动下载模型到models目录

**Q: 依赖安装失败？**
A:
1. 升级pip：`pip install --upgrade pip`
2. 使用国内镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

### 5.2 使用问题

**Q: 分析结果不准确？**
A:
1. 检查输入数据格式是否正确
2. 确保包含payload字段
3. 提供更多上下文信息

**Q: 处理速度太慢？**
A:
1. 使用GPU加速
2. 启用批处理模式
3. 增加并发数

**Q: 如何添加自定义攻击类型？**
A:
1. 编辑`src/agents/router_agent.py`中的关键词映射
2. 更新`data/knowledge_base/`中的知识库
3. 重启系统

### 5.3 API问题

**Q: 返回422错误？**
A: 检查请求体格式，确保必填字段完整

**Q: 返回500错误？**
A: 查看日志文件：`logs/api_server.log`

**Q: 如何设置API认证？**
A: 编辑`config/api_config.yaml`配置认证方式

## 6. 最佳实践

### 6.1 数据准备最佳实践

1. **数据清洗**
   - 去除重复数据
   - 标准化时间格式
   - 统一字段名称

2. **数据增强**
   - 添加上下文信息
   - 包含原始日志
   - 提供攻击特征

3. **数据格式**
   - 使用UTF-8编码
   - JSON格式确保正确转义
   - 避免特殊字符

### 6.2 性能优化建议

1. **硬件优化**
   - 使用SSD存储
   - 增加内存容量
   - 使用高性能GPU

2. **软件优化**
   - 调整批处理大小
   - 使用缓存机制
   - 并行处理

3. **配置优化**
   ```yaml
   # 推荐配置
   performance:
     batch_size: 32
     max_workers: 8
     cache_size: 1000
     gpu_memory_fraction: 0.9
   ```

### 6.3 安全建议

1. **访问控制**
   - 设置强密码
   - 启用API认证

2. **数据保护**
   - 加密敏感数据

### 7.1 日志查看

```bash
tail -f logs/system.log

# 查看错误日志
grep ERROR logs/system.log

tail -f logs/api_server.log
```

#### 日志级别说明
- **DEBUG**：调试信息
- **INFO**：一般信息
- **WARNING**：警告信息
- **ERROR**：错误信息
- **CRITICAL**：严重错误

### 7.2 常见错误及解决方案

#### 错误1：ModuleNotFoundError
```
ModuleNotFoundError: No module named 'transformers'
```
解决方案：
```bash
pip install transformers
```

#### 错误2：Permission denied
```
PermissionError: [Errno 13] Permission denied: './models'
```
解决方案：
```bash
# Linux/Mac
chmod -R 755 ./models

# Windows（以管理员身份运行）
```

#### 错误3：Connection refused
```
requests.exceptions.ConnectionError: [Errno 61] Connection refused
```
解决方案：
1. 检查服务是否启动
2. 检查端口是否被占用
3. 检查防火墙设置
